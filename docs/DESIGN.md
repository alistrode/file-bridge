# File Bridge 2.0 设计与验收目标

这是 File Bridge 内部的独立实现，不依赖 SSH、SSH Relay Pro、它的模块、配对身份、MCP 或信道。1.0 的 `source/server.js` 和 Cloudflare 启动脚本保留，新版运行入口为根目录的一键启动脚本。

## 已选方案

- 两端运行完全相同的程序。以一次性配对码进行 OPAQUE 密码认证密钥交换，绑定各自 Ed25519 公钥。配对码 5 分钟有效，单次使用；保存设备公钥和独立连接秘密，下次自动连接同一身份。
- 传输使用 MQTT.js 的 WSS 连接，默认同时接入 Mosquitto 和 EMQX 的公共测试中继。每个配对具有随机独立主题；数据用方向派生密钥进行 AES-256-GCM 加密，并通过 Ed25519 签名校验发送方身份。一个中继故障时继续使用另一个，全部故障后持续恢复。
- 不将 MQTT 的代理确认当成对端确认。发送队列先落盘；接收端写入、同步并保存检查点后才确认。文件分块传输，断线/进程重启后可以续传，完成后核对 SHA-256。确认丢失可以重发，接收记录按任务 ID 去重。
- 每次连续失败的等待依次为 1、2、3……秒；不指数退避。稳定连接 30 秒后重置失败计数。每 5 秒发起双方心跳，20 秒未得到响应则显示对端离线。系统计时器有上限，超长连续故障最终使用计时器可表示的最大等待，而不会溢出成紧密循环。
- 桌面托盘由 Electron 提供；点击打开应用自带、启用沙箱的 File Bridge 网页窗口。后台重启后，已打开的窗口自动取得新入口恢复页面。关闭网页不停止后台；可以单独退出托盘或明确停止本实例。监督进程会恢复崩溃的后台程序。
- 当前账户登录自启动和“自动启动时打开网页”是两个独立偏好。自启动名称按私有 profile 的哈希隔离。不会创建系统级服务，也不会假装未登录桌面就能显示浏览器。Windows 使用当前账户 Startup 快捷方式；Linux 使用当前用户 XDG autostart。
- 双方都能请求对方打开网页。只打开接收端自己的回环网页，不接受远程任意 URL 或命令。托盘在线时由应用窗口处理，没有桌面托盘时才请求系统浏览器。默认需接收方确认；用户可以针对某个配对设备显式允许自动打开。请求 5 分钟后过期，接受状态先保存再执行，重发不反复弹窗。
- 轮转 JSONL 日志：单份 2 MiB，最多三份备份。记录连接、重试、确认、进程退出、错误阶段及安全的错误码，不记录配对码、访问令牌、密钥或传输内容。

## 隔离边界

默认私有目录为 `~/.file-bridge-v2`，可通过 `--profile-dir` 指定独立目录。每个实例监听随机的 127.0.0.1 端口，启动锁覆盖 GUI/后台并发启动。网页令牌按每次运行生成，Cookie 为 HttpOnly/SameSite=Strict，写请求还要通过同源检查和专用请求头。

新版本不启动 Cloudflare，不占用旧版 8790/8876 端口，不读取旧版 `data/`、`received/`、`current-url.txt`。测试只使用自己的 profile 和进程；共享 Win10 不重启、不结束其他任务。

## 交付与验证标准

单元测试检查加密、重试、访问保护、重发去重及检查点恢复；真实公网测试检查双向配对、文件逐字节往返、双方重启、单/双中继故障及持续传输；桌面/浏览器测试检查托盘、偏好、快捷方式、网页操作、截图和移动宽度。

视觉基准是当前实现经过检查后的截图；没有用户提供的外部设计图。逐像素检查只比较同一平台、字体、视口和稳定真实数据下的两次独立浏览器渲染，不声称 Linux 与 Windows 字体渲染相同，也不声称与未知设计图一致。

## 不能靠客户端消除的边界

公共测试中继没有本项目可控制的可用性承诺，同时故障、服务端限流或设备断电时会等待恢复。双中继、持久化队列和故障注入验证降低影响，不构成“永不断线”保证。跨机器时钟相差超过两分钟会拒绝通信帧；大文件传输速度取决于公共中继。桌面交互需要真实登录会话，Linux Electron 需要可用的用户命名空间沙箱和图形桌面。
