# File Bridge 3.0 交接与验收

日期：2026-10-27（UTC+8）。项目长期分支：`projects/file-bridge`。

## 最终行为

只有一个主机运行网站和 Cloudflare 隧道。访问者用普通浏览器打开同一个完整网址，发送文字、图片和文件；不需要双端客户端、设备配对、设备列表、公共 MQTT/WSS 中继、托盘或远程打开另一台设备的网页。

保留并适配了持久队列、断线重试、浏览器刷新恢复、分块续传、分块和整文件校验、主机保存确认、去重、归档、网站健康检查、网站及隧道崩溃恢复、日志轮转和可选的当前用户登录自启。Windows 短暂文件锁导致状态替换失败的问题已修复；替换时重试并保留原有效状态，启动阶段也会重试。

## 远端运行位置

- 项目：`E:\xxm\file-bridge-single\`，包含 `dev/`、`backups/`、`release/`。
- 当前程序：`dev/`；状态和接收内容：`dev/var/`。
- 当前公网入口：`dev/var/current-url.txt`，不提交仓库。
- 当前网站只监听 `127.0.0.1:18791`，由 Cloudflare 提供公网 HTTPS。
- 当前以 Acer 用户运行。`FileBridge-Single-Host` Windows 任务维持本次运行，无登录触发器；任务不设运行时长上限，失败时由系统按一分钟间隔最多重启三次。
- 登录自启是可选功能，本次只验证并清理测试项，没有擅自打开正式登录自启。普通使用者只打开浏览器网址。

停止当前实例：

```powershell
node source/host/cli.cjs stop --profile-dir E:\xxm\file-bridge-single\dev\var
```

再次启动、查看、打开网页分别用相同 profile 的 `start`、`status`、`open`。主机应用明确停止后不会自行重启。旧验证目录中的文件保留作为回退资料，不作为当前运行程序。

## 依赖与范围

应用无 npm 运行依赖。主机需要 Node.js 22+ 和官方 cloudflared。本次 Windows 使用现有 Node.js v26.4.0 和 cloudflared 2026.10.4；Linux 使用 Node.js v24.19.0。

- Node.js：[固定版本来源](https://nodejs.org/dist/v26.4.0/)，遵循 Node.js 及其所含组件许可证。
- cloudflared：[固定版本来源](https://github.com/cloudflare/cloudflared/releases/tag/2026.10.4)，Apache-2.0。
- 浏览器仅用于访问或验收，不是主机端 Electron 运行时。Windows 浏览器验收脚本使用 Node.js 标准库连接隔离的浏览器，无需给应用安装 Playwright 或 Electron。

当前使用临时隧道，重建会换网址。命名隧道和固定域名入口已支持，但未提供账户配置和域名绑定，因此本次没有冒称已部署固定域名。临时地址变化后，浏览器存储不会跨网站地址自动迁移；重新选择相同文件可复用主机分块。长期使用固定域名更适合自动恢复队列。

完整配置、保留期限、源码入口与运行命令见根目录 README.md。运行时、主机状态、接收内容和访问凭据均不提交源码仓库。
